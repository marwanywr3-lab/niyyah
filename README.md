Development release 0.1. Frontend: GitHub Pages. API and database: Cloudflare Workers and D1 in the owner’s Cloudflare account. API: https://niyyah-api.barboodmarwan.workers.dev. No custom domain.

## Run

Node 22+: `npm ci`, `node scripts/build.mjs`. Serve `public/` locally. Deploy Pages via the included Actions workflow after choosing GitHub Actions as the Pages source.

## Implemented

Arabic responsive PWA; offline shell and optional Quran package; Adhan prayer calculation with method and Asr selection; city coordinates; true-north qibla bearing; Umm al-Qura date and personal adjustment; local optional prayer records, personal duas, verse reflections and bookmarks; JSON export/restore; username/password auth API with salted PBKDF2-SHA256 (100,000 iterations), random hashed session tokens, 24-hour sessions, throttling and single-use recovery codes; optional client-encrypted AES-GCM snapshot vault with conditional version writes. Guest records do not upload on registration. Bearer sessions stay in sessionStorage. Vault phrase is separate from account password and must be backed up independently.

## Sana v0.2 operations

Set GEMINI_API_KEY as a Worker secret. Set SANA_DISABLED=true to stop provider requests. Authentication and per-question consent are required. Questions only (no private records or conversation history) are sent to Google; no message text is stored in D1. The ai_requests table stores pseudonymous usage accounting. One in-flight request per account, 10-second spacing, 1,200-character input limit. Each account gets 10,000 tokens per calendar-month anniversary cycle (UTC; last-day clamp). Reservations include system prompt and max output and settle to usageMetadata.totalTokenCount. Unknown failures retain the conservative reservation. Stale reservations stop blocking new requests after 60 seconds without refund. A separate lifetime global budget uses 5 USD-micros per token, above the fixed model input/output list rates, with a 1,000,000-micro ($1) ceiling; this is an application-side conservative allowance, not a Google billing report. It covers this app only. No search/tool calls or automatic provider retries. Request IDs prevent duplicate charges. Religious text and references cannot be generated by this path: Gemini returns a topic enum and the server selects the final vetted support copy. Run node scripts/test-sana.mjs for quota and concurrency tests.

## Religious library v1

22 classical Arabic adhkar/dua excerpts from Sahih al-Bukhari and Sahih Muslim, source-checked against the linked narrations on 2026-11-06. See SOURCES.md and data/adhkar.json. This is a selected library, not all of Hisn al-Muslim; independent scholarly review is pending. Modern commentary/translations are not copied. Texts and references are served from a closed library; Gemini only selects an existing entry or category. No generated scripture, hadith, citations or fatwas are displayed. The frontend supports categories, search, local favorites, source links and counters only for attested numeric repetitions. Null count means no specific number is attested in the cited narration. The same catalog is seeded into D1 (seeds/adhkar-v1.sql) and packaged locally for offline use. The released app uses the versioned source bundle, not arbitrary DB edits. Withdrawal requires updating the source status and redeploying/re-downloading; old offline copies are not silently revoked. Direct scripted fetch of source pages returned HTTP 403, so textual checking used browser-accessible web source pages; metadata/count validation and retrieval integrity tests are automated.

Four additional source-checked knowledge cards cover intention (Bukhari 1), steady deeds (Bukhari 6464), gentleness (Bukhari 69) and learning/helping others (Muslim 2699a). They are available in Discover and Sana as stored-text retrieval with citations. Worker deployment is now API-only (~57KB); its root redirects to GitHub Pages. Quran and other frontend assets remain on Pages, reducing deploy size and separating concerns. Live Gemini 3.5 Flash-Lite retrieval was verified with the guidance supplication and its exact stored text and Muslim 2721a reference.

## Discover and page reader

54 source-checked original educational summaries with citations, four learning paths, local read-progress, and optional comprehension quizzes. No scholar approval is claimed. Sana selects only among up to six keyword-retrieved article IDs and returns stored summaries/references, never invented quotations. Quran page mode is the default; it renders the owner’s exact source body lines across 604 source-defined pages, using the unmodified OFL-licensed Amiri Quran font. Page/surah/juz navigation, page bookmarks, font scaling, arrow keys/swipes, offline page/font downloads and continuous-study mode are available. Original malformed verse markers remain visible and flagged; this is not a verified printed Madinah mushaf. To rebuild the page package: node scripts/build-quran-pages.mjs PATH_TO_APPROVED_ARQURAN_TXT. Test full line preservation with node scripts/test-pages-and-discovery.mjs PATH_TO_APPROVED_ARQURAN_TXT.
